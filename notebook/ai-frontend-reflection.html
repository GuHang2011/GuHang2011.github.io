AI writes code faster. Where do I go from here as a frontend developer?

Making a page is getting easier. Working on my GitHub portfolio has made me think about what to study next, and what still makes me uneasy.

Saving time comes with some unease

Using AI on projects has left me with mixed feelings. It helps me put a page together and ask about unfamiliar code as I go. That is useful. Yet seeing a first draft appear so quickly makes me wonder whether the things I spent time learning are still worth studying.

The change is particularly visible in frontend work. A description can become a page with a layout, forms and interactions. Someone using it may care much more about whether it works than who wrote the code. That is an uncomfortable thought for a developer.

I doubt that learning a few AI tools will settle that anxiety. Tools and project requirements will keep changing. For now, I want to get better at using AI while still understanding what I am handing over.

Working on my own site made this clearer

I have been working on my GitHub site and adding project demos. At first I kept wanting more content and animation. After several rounds, parts of it still felt awkward: the type size was off, some sections demanded too much attention, and adding more material made it harder to see what mattered.

Generating a page and making it work well require different kinds of attention. AI can offer plenty of options. I still need to look at where a first-time visitor will start, whether the project links are easy to find, and how the text reads on a phone. Sections also need to work together; a set of attractive pieces can still feel like several unrelated websites.

The same applies to behaviour. A search box may return results for an ordinary query, but what happens when someone searches again before the first request finishes? A late response might replace the newer results. A screenshot cannot show that. This is one place where frontend experience still helps.

How I want to study from here

I will keep learning frontend development. Before picking up another framework, though, I want to ask whether a project actually needs it. I would like to spend more time understanding the tools already in use: why requests interfere with each other, where component state belongs, or what makes the browser slow. Changing tools does not automatically resolve those questions.

Using AI to write code takes practice too. I do not want to hand over a vague request, receive a large change I cannot follow, and keep asking for fixes. I want to work on smaller problems, understand the existing code first, then read the changes and run them myself. If an explanation does not make sense, I need to stop and investigate.

I also want to spend some time beyond the frontend itself: where the data comes from, how a failed request recovers, and how an AI response should be presented. An AI application needs more than a text box that returns an answer. What does someone see while waiting? Can they stop it? Can they continue after an error? Studying those parts together with the interface interests me.

There is only so much time, and I cannot study everything in depth. For now I will start with the business systems and interactions I know, then follow the questions that come up. That feels more manageable than collecting courses and losing track of why I saved them.

Start with the projects already in hand

I cannot say what frontend jobs will look like in the future. As routine work gets easier, I need to reconsider some advantages that came from practice. I do not want that uncertainty to make me abandon everything I have learned.

For future GitHub updates, I want fewer demos added just to increase the count and more records of changes. For a low-code form, for example, I could explain why I chose a state design, which AI suggestion I left out, and what I found after making the change. The record only needs to be clear enough for me to understand my reasoning when I return to it.

I still enjoy turning an idea into something people can click and use. AI has made it much easier to begin. I want to keep working on the parts that take patience afterwards. Next time, I will pick a small problem in an existing demo, fix it and write down what happened.
