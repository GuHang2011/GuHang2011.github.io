# Schema-driven Form Studio / 配置驱动表单工作台

一个围绕动态表单、字段配置和校验边界整理的低代码学习示例。它借鉴本地 Vue 教学材料中“字段描述 + 渲染器”的思路，重新使用合成字段和公开代码实现；不等同于原系统，也不包含原始业务配置、数据库、账号或用户数据。

## 设计要点

- **Schema 与 renderer 分离**：字段的 key、label、type、options 和规则保存在 JSON 结构中，渲染器只负责把受支持的类型映射为原生控件。
- **显式校验**：必填、邮箱格式、最小长度和选择项规则在提交时统一执行；错误紧邻字段，并通过 `aria-invalid` 和 `aria-describedby` 连接辅助技术。
- **可观察的配置变化**：在线页支持新增、删除、排序、标题编辑、必填切换，以及文本、邮箱、选择、多行文本、数字、日期六种类型。支持检查并应用 JSON；选项和范围规则可在编辑区调整。
- **安全边界**：示例只创建受支持的原生控件，不把 schema 当作 HTML 执行。真实项目仍需服务端重新校验、权限判断、持久化和审计。

## 与本地项目的关系

本例抽取的是通用的“配置驱动表单”设计思想，参考了本地 Vue 项目中的字段描述结构。公开版本使用合成的教学申请字段，未复制原始页面、业务数据或私有配置，也没有宣称这是一个完整低代码平台。

## 本地运行

```bash
python -m http.server 8000
```

在网站仓库根目录运行，再打开 `http://localhost:8000/demos/low-code-form/`。项目没有运行时 CDN 或构建依赖。

## 工程笔记与测试

[字段键、输入保留与配置边界](design-notes.md) · [独立校验核心](schema.mjs) · [10 项测试](schema.test.mjs) · [验证记录](../frontend-verification.md)。在本目录执行 `node --test schema.test.mjs`。

默认配置从 `schema.json` 加载。JSON 导入失败时保留旧配置；成功时清空预览输入，普通排序和语言切换保留输入。复制只写入本机剪贴板；校验不会提交表单，也不会持久化内容。

这是自定义应用 schema v1，不宣称支持 JSON Schema 标准。新增于 2026-10-22，采用 AI 辅助实现与整理，未执行原 Vue 业务系统的集成测试。这里的工程检查不代表原系统验收。
