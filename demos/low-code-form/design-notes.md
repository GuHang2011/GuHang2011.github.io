# 低代码表单：配置、渲染与校验的边界

整理日期：2026-10-22。新增的公开学习示例使用 AI 辅助实现与校对，字段与输入均为合成教学内容。本地 Vue 项目的字段描述结构启发了设计；这里没有复制原页面、业务配置或数据，也不宣称是完整低代码平台。

## 让配置只有一个来源

`schema.json` 是默认配置，界面通过 fetch 加载，再经 `checkSchema` 检查版本、数量、类型、键与规则。字段预览、侧栏和 JSON 编辑区均由当前内存配置派生。若把默认字段同时写入 JSON 和 JavaScript，两处就可能在维护中分叉。

## 使用窄的配置语言

本例支持六种控件：文本、邮箱、选择、多行文本、数字和日期；最多 12 个字段。配置是项目自定义的 v1 格式，**不是 JSON Schema 标准实现**。不接受脚本、动态组件路径或可执行表达式。标题采用 `textContent`，不当作 HTML 解释。选项与长度、数字范围可在 JSON 编辑区调整。

受限表达能力换来可预测渲染。复杂条件表单可以引入规则解释器，但需定义循环依赖、空值、规则优先级和后端一致性，不能仅靠更多字符串拼接解决。

## 字段键是数据身份，不是位置

字段排序后必须保留原值。删除一个字段再新增时，不能只用数组长度产生 key，否则可能重复。`nextKey` 查找未使用的键；导入配置也拒绝重复键和保留对象键。选择控件先添加选项，再赋值，避免重渲染时看上去清空而内部仍保留旧值。

## 校验必须区分缺失与零

必填数字的 `0` 是合法值，不能用真假判断识别缺失；可选字段为空时应跳过最小长度检查。选择项校验成员关系，数字检查有限性与上下界，日期检查真实日历，而不仅仅匹配格式。前端校验改善使用体验；后端仍需要独立复验。

## 导入配置必须是一次完整操作

JSON 先解析、检查通过，再替换现有配置。解析错误、重复字段或不支持的类型只显示错误，不破坏已有表单。成功导入会清空旧输入，因为新字段可能重新使用相同键却改变语义；页面对此明确提示。普通排序与语言切换则保留输入。

## 核对路径

1. 空表提交，检查必填错误与焦点。
2. 填入合成内容、选择选项，排序后确认值仍在。
3. 删除再新增字段，确认键不会重复。
4. 切为数字类型并输入 0；切为日期类型检查日历值。
5. 导入重复键或无效 JSON，应拒绝并保留现有配置。
