# PhD application review checklist

Use this list before sharing the profile with a prospective supervisor.

## Evidence

- [ ] Each featured project states the problem, my contribution, the stack, and one limitation.
- [ ] At least one project includes a live demo and a short source-reading path.
- [ ] Claims about speed, scale, accuracy, or impact have a measurement or are labelled as future work.
- [ ] Screenshots show a synthetic or redacted scenario and have useful captions.

## Reproducibility

- [ ] A new reader can install or open the project without private credentials.
- [ ] Configuration examples use placeholders and explain required environment variables.
- [ ] Data transformations and evaluation steps are documented.
- [ ] The README records known limitations and the date of the latest check.

## Academic presentation

- [ ] The homepage leads with research interests and evidence, not a long technology list.
- [ ] Project names and links are stable and consistent across the homepage and repositories.
- [ ] A short research narrative explains how engineering practice leads to research questions.
- [ ] A redacted CV or publication list is shared only after checking contact and institution privacy.

## Final safety check

- [ ] Search the repository for passwords, tokens, private keys, phone numbers, email addresses, student identifiers, and internal URLs.
- [ ] Remove databases, upload directories, caches, logs, build outputs, and local environment files.
- [ ] Review commit history for accidentally committed secrets before making a repository public.
