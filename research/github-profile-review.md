## Repositories

每个重点仓库的 README 使用统一结构：

```text
一句话定位
研究/工程问题
个人负责部分及上游归属（需可核对）
在线演示或截图
方法与技术栈
目录导览
运行步骤
结果与证据范围（注明实际检查日期）
局限性与下一步
许可证与数据说明
```

仓库元数据需同时检查：Description 使用“问题 + 方法 + 公开内容”；Topics 使用英文小写，并与实际内容一致，例如 `multimodal-learning`、`model-evaluation`、`pytorch`、`reproducible-research`。设置准确的许可证、默认分支和 Pages 地址，保留第三方来源与许可声明。公开材料排除密钥、原始数据库、生产日志、上传文件、真实学生数据和未经脱敏的内部截图；演示截图说明合成数据性质。

KAPT 的组件验证记录不能代替 KICP 的研究实验结果。外部数据要求、合成示例、源码审阅和实际运行检查应分别说明；统计测试数量时链接对应记录，不将文档更新日期写成新验证日期。

学习笔记仓库需要注明资料来源、阅读日期、最小实验和未解决问题，避免把笔记包装成论文结论。

## 博导通常会关注

- 是否能说明数据为何重要、现有方案哪里不足。
- 是否有基线、指标、误差分析和失败案例。
- 团队项目中个人负责的模块、取舍和边界。
- 别人能否按 README 在干净环境中运行最小示例。
- 是否主动说明数据偏差、隐私限制、外推风险和当前不能声称的结论。
- 提交和笔记更新是否对应真实实现、实验或复查工作。
- 核心 README、项目摘要和图表说明是否提供英文版本。
