02 / DECISIONS

Three decisions to inspect in the code

01

Share business state; isolate platform APIs

Web and uni-app read the shared logic; each platform supplies network, storage and device access. The platform adapter checks response envelopes and session ownership.

Read the implementation note →
02

Keep failed photos visible

A serial upload queue tracks four states. Identity changes invalidate late callbacks; failed items can be retried or removed. Ignoring a callback does not cancel a server write.

Read the implementation note →
03

Check the files being delivered

VERSION coordinates the applications. A manifest, file-set comparison and ZIP byte checks make stale artifacts easier to detect.

03 / REPRODUCE

Start with a pinned release

The public release uses frontend/ and backend/. Web code lives in frontend/src, the mobile app in frontend/mobile, and shared state in frontend/shared. Read platform.ts and usePhotoUpload.ts before following the corresponding tests.

For Windows local startup, install Node.js 18+, npm and JDK 8; dependency downloads need network access. Clone the release, then run the two startup commands in separate terminals at the repository root. The backend prompts for the initial administrator password.

git clone --branch v1.2.2 --depth 1 https://github.com/GuHang2011/shuyang-home.git
cd shuyang-home

# Terminal 1, repository root
powershell -ExecutionPolicy Bypass -File .\Start-Backend.ps1 -Build

# Terminal 2, repository root
powershell -ExecutionPolicy Bypass -File .\Start-Frontend.ps1

# Open http://127.0.0.1:8888
