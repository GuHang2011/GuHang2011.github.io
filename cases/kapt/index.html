01 / ENGINEERING STUDY

Make the evaluation contract explicit

Small components with clear inputs, state and failure conditions.

The local project combines the third-party KANO baseline with KAPT study code. Its evaluation helpers needed clearer boundaries: a model checkpoint is not a prediction file, averaged metrics are not an ensemble metric, and the epoch with the best validation score is not necessarily the epoch when training stops.

Early-stopping state

Validate mode, patience and score inputs. Keep best epoch separate from stop epoch and make a stopped run stay stopped.

Prediction-level ensembles

Align rows by sample ID, check labels and prediction ranges, then evaluate the averaged predictions. Keep threshold choice on validation data.

Prompt tensor contracts

Task prompts, node-feature pooling and residual injection with explicit shapes. Pooling uses node features and graph IDs; it does not consume graph edges.

What this study establishes

  • It documents local engineering changes to evaluation helpers and a reading path through KANO-derived study code.
  • It does not establish molecular benchmark performance, novel model contributions or completed end-to-end training.
  • Public examples contain no original datasets, trained weights, production logs or private checkpoint files.

KANO is credited to its original authors. The upstream MIT notice is preserved where applicable. The replay and reading diagram on this page are newly prepared synthetic learning material.
