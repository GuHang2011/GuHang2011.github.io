# 辅导员系统：任务流程与发布验证

**工程案例 · Vue 3 + Spring Boot · 既有验收记录：2026-10-13**

## 问题

校园事务经常同时涉及多人办理、材料上传、截止时间与审核。进度达到 100% 不应自动等同于审批完成。另一个工程问题是：已经通过验收的网页和后端，是否就是最终部署包中的那一份？

## 工作流设计

任务支持多人独立进度、开始与截止时间、材料提交、验收、退回批注、延期与取消。首页区分当前待办与尚未开始的安排；需验收的任务在审核通过后才计入完成。批量审核会随筛选清除不再可见的选项，减少对隐藏任务的误处理。

服务端按本人、班级或学院范围授权。学生关怀正文与一般行政信息采用不同可见范围；内部聊天对联系人、会话和附件访问分别检查。浏览器端提供弱网重试与提交反馈，服务端处理重复请求与内容冲突。

## 将验收与产物绑定

发布流程记录后端程序、生产网页目录与浏览器报告的 SHA-256。打包前重新计算并比较；网页或程序发生变化、报告变更、浏览器失败或跳过、重启检查未完成时，停止出包。打包后再次核对复制后的产物，生成包内清单及 ZIP 校验值。

```text
生产构建 → 隔离验收 → 固定三份校验值
                           ↓
                    打包前重新比对
                           ↓
                 脱敏证据摘要 + 文件清单
```

这能发现测试后误改产物、使用陈旧页面或混入旧版本资源等问题。哈希说明产物一致性；报告真实性和发布权限仍需要独立保障。

| 20261013 发布验收摘要 | 17 项浏览器检查通过，失败、跳过与不稳定重试均为 0 | 本机隔离环境；含生产桌面网页及独立 H5 检查 |

## 研究延伸与限制

可进一步评估业务状态、页面动作与服务端授权是否一致，以及“测试结果绑定发布产物”能否降低配置与版本混用错误。下一步需要明确故障模型与对照实验，而不是把测试通过直接描述为用户效率提升。

当前设计按单后端实例运行。本机记录不覆盖目标 MySQL、正式 Linux 服务、证书、正式名单迁移或真实外部模型；旧运行时与依赖还需升级评估。AI 提供模板回退并要求人工核对，真实模型效果尚需独立评估。
